## 判断と棄却案

- 棄却：distブランチにwheelをコミットする方式（一時ブランチ×3で受け渡し，orphanブランチ利用）— 実装まで行ったが，ユーザーが「ブランチ乱立は危険」と判断して破棄．コードはgit checkoutで破棄済み
- 棄却：actions/upload-artifact + retention-days: 1 — ユーザーの経験上，一時保存でも月間保存量に加算されるため
- 棄却：固定タグrelease（dist-latest）方式 — 設計まで固めたが，PyPI trusted publishingに方針転換したため実装せず
- 棄却：actions/cacheをジョブ間受け渡しに使う方式 — ユーザーが「キャッシュもどうせ制限にかかる」と判断
- 棄却：ビルドジョブと公開ジョブの完全分離（レビュー指摘3の完全対応）— artifact/cache/release全て使用不可の制約下では，受け渡しにビルドジョブへの`contents: write`付与が必要になり，`contents: write`はワークフローファイル改変→trusted publisher乗っ取りを許すため`id-token: write`付与と危険度が実質同等．分離の利得なし
- 採用：2フェーズ構成（フェーズ1: 全OSテストビルド公開なし → needs → フェーズ2: 同一コミット再ビルド＋各OSジョブが直接publish）— 根拠：ファイル受け渡しなしで「全ビルド成功後にのみ公開」の順序保証を実現し，コード起因の部分公開を排除．コストはビルド時間2倍だが手動リリース用途で許容
- 採用：`uv publish --trusted-publishing always` — 根拠：定番の`pypa/gh-action-pypi-publish`はDockerアクションでLinuxランナー専用のため，windows/macosジョブから直接公開できない．uvは全OSで動きOIDC対応
- 採用：`--check-url https://pypi.org/simple/uxsim/` を残す — 根拠：フェーズ2の部分失敗後の再実行時に既存ファイルをスキップして欠落分だけ追加公開できる．外部レビューは「PyPIでは原則不要」としたがClaude側の理解と相違し，残す方が安全と判断
- 採用：environment: pypi（GitHub environment，required reviewers）— レビュー指摘4．公開直前の人間承認ゲート．フェーズ1失敗対策ではない（それはneedsの役割）
- 採用：cibuildwheel==4.1.0，uv==0.11.28に固定 — レビュー指摘7の部分採用
- 見送り：nanobindのpin — pyprojectの`build-system.requires`から非固定で入るため，CIBW_BEFORE_BUILDでのpinは実効性がない．固定にはpyproject変更（本家コード変更）が必要
- 見送り：GitHub ActionsのSHA固定 — リポジトリ内他ワークフロー（全部タグ参照）との一貫性の問題なので今回のスコープ外

## 罠と注意点

- `permissions:`をジョブに明示すると未指定の権限は付与されない．`id-token: write`だけ書くと`contents: read`が消える（publicリポジトリのcheckoutで実害が出るかは未検証だが明示が安全）
- Trusted PublisherはOwner/リポジトリ名で照合されるため，フォーク（toruseoagent/UXsim）から実行する場合と本家（toruseo/UXsim）から実行する場合で別々の登録が必要
- GitHub environmentは参照されると保護ルールなしで自動作成される．required reviewersゲートを効かせるには事前の手動設定が必要
- PyPIは一度公開したバージョン番号を削除しても再利用できない．起動前に`__init__.py`のバージョン更新が必須
- rebase後の`git push fork main`はnon-fast-forwardで拒否される．fork側の固有コミットがrebase前の同内容コミットであることを`git log HEAD..fork/main`で確認してから`--force-with-lease`
- GitHub ActionsのYAMLはアンカー（&/*）非対応．CIBW設定の重複排除はworkflowレベル`env:`で行った
- ビルド対象は既存build-wheels.ymlの踏襲で Windows AMD64 / Linux x86_64 / macOS universal2 × cp310-cp314 ＋ sdist．Linux ARM等は含まれない（ユーザーに伝達済み，異論なし）
