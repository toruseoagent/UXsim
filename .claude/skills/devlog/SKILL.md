# 開発ログ作成スキル

## 手順

1. 現在の日時を取得する: `TZ=Asia/Tokyo date '+%Y%m%d%H%M'`
2. 今回の会話で行った作業を振り返り、テンプレートに沿って内容をまとめる
3. `devlog/YYYYMMDDhhmm_{タイトル}.md` にファイルを作成する

## ファイル名

`devlog/YYYYMMDDhhmm_{タイトル}.md`

- 日時は日本標準時（`TZ=Asia/Tokyo date '+%Y%m%d%H%M'`）
- タイトルは内容を端的に表す日本語（例：`cppノードモデル高速化`）

## テンプレート

```markdown
# {タイトル}

## 目的
{1-2文で、なぜこの変更が必要か}

## 作業内容
{何を実装・変更したか。箇条書きで、各項目にファイルパスを明記。
「実装」セクションは変更ファイルの一覧索引、こちらは変更内容の説明。}

## 検証
{テスト結果、動作確認。数値があれば表で。
予備実験・sanity checkの数値結果もここに含める。
テスト: 新規追加数・既存テスト数・合計pass数を明記。
sanity check: 初期値と最終値を対比する表を最低限含める。
図を生成した場合はここに埋め込む。}

## 実装
{変更・新規作成したファイルの一覧。ファイルごとに1行。}
- コード: `{ファイルパス1}`
- コード: `{ファイルパス2}`
- テスト: `{テストファイルパス}`

## 再現
{テスト実行コマンド、またはsanity check等の実行コマンド。}
```

## 注意事項

- 言語は日本語で書く
- 「作業内容」と「実装」は役割が異なる。「作業内容」は変更の説明、「実装」は変更ファイルの索引
- 検証セクションには具体的な数値を必ず含める（テスト数、実行時間、精度など）
- 再現セクションのコマンドはコピペで実行できる形にする。ベンチマークや検証用スクリプトが別ファイルにある場合は、そのファイルパスを実行するコマンドを記載する（例: `python3 devlog/bench_xxx.py`）
- **計算効率化の場合**: 検証セクションに計算速度またはメモリ使用量のbefore/after比較表を必ず含める（例: 実行時間、スピードアップ倍率、メモリ消費量など）
